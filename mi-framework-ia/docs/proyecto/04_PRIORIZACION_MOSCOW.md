# Priorización MoSCoW

**Proyecto:** Aplicativo web de preperitaje vehicular con IA

## Must have (imprescindible para el MVP)
| Historia | Justificación |
|---|---|
| Registro del usuario | Necesario para asociar vehículos y resultados a una cuenta. |
| Registrar vehículo | Base de datos mínima para que el análisis tenga contexto. |
| Subir fotografías | Función central del producto: sin fotos no hay análisis. |
| Responder preguntas sobre el vehículo | Complementa la información visual, requerido por el análisis de IA. |
| Obtener análisis preliminar mediante IA | Es el diferenciador principal del proyecto; sin esto no hay producto. |
| Estimación del valor | Es uno de los dos objetivos centrales que el cliente pidió explícitamente. |

## Should have (importante, pero no bloquea el MVP)
| Historia | Justificación |
|---|---|
| Ver resultado del preperitaje | Mejora la experiencia, aunque el resultado podría mostrarse inline sin un informe aparte. |
| Protección de la información | Importante por manejar fotos y datos personales, pero puede resolverse con medidas básicas en una primera versión. |
| Corrección o repetición del análisis | Aporta valor, pero el usuario podría iniciar un nuevo preperitaje manualmente como workaround. |

## Could have (deseable si sobra tiempo)
| Historia | Justificación |
|---|---|
| Recomendaciones para el peritaje profesional | Añade valor orientativo, pero no es indispensable para validar la idea del producto. |

## Won't have (fuera de alcance por ahora)
| Historia | Justificación |
|---|---|
| Integración con talleres o peritos reales para agendar cita | Requeriría alianzas externas y no es viable en el tiempo del semestre. |
| Historial comparativo de mercado con datos reales de precios | Requeriría acceso a fuentes de datos externas de pago, fuera del presupuesto académico. |

## Resumen del criterio de priorización
Se priorizaron primero las historias que forman el flujo mínimo funcional (registro → datos del vehículo → fotos → preguntas → análisis IA → valor estimado), dado que sin ellas el producto no cumple su propósito. Las historias relacionadas con seguridad, informes y repetición del análisis se consideraron importantes pero no bloqueantes para una primera entrega funcional (MVP) dentro del tiempo del semestre.
